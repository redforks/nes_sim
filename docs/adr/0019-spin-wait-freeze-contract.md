# Spin-wait freeze contract: synthesized VBL exit, replayed device effects, line-level wake

Spin-wait freeze was introduced to make repeated poll loops unobservable: while a declared loop is frozen, the rest of the machine keeps advancing on the same dots and the program resumes as if the loop had executed. Review found that the original contract had drifted. Only `$2002` status polls were covered: device-register polls (`$4015` APU status, `$4016`/`$4017` controller ports) were excluded, so input/IRQ wait loops still burned dots. The frozen wake path called the CPU's own edge-latching interrupt detectors, mutating CPU state on a frozen dot. The original spec pinned loop-top re-execution as the resume, but the implementation performs the status poll read itself and exits through the back edge: re-execution shifts later reads off the counterfactual grid, changes which frames suppress VBL, and misconverges cycle-counted initialization such as `nmi_sync`. A `$2007` poll could also declare and swallow PPUDATA's read-buffer refill and v-increment. This ADR records the finalized contract; it changes no code.

## Considered options

- **Loop-top re-execution for every wake (original pin)**: rejected as canonical. Re-executing the fetch-decode prefix after the flag becomes visible puts later reads off the grid the executing loop would have followed; VBL suppression and cycle-counted setup diverge. It remains the fallback for shapes the synthesis does not cover.
- **Kept detector calls in the frozen wake path**: rejected because an edge-latching detector mutates CPU state on a dot where no instruction executes. Reading the machine-published levels instead keeps wake dots on the counterfactual grid with no extra state mutation.
- **Repeated bus reads or a synthetic poll value for frozen device polls**: rejected. Repeating the read would deliver device values to the program inside the freeze and drift the device state; a fabricated value would do the same. Only the device-side effects are replayed; the real loop-top read after wake consumes the real value.
- **Excluding device polls or allowing PPUDATA/KIL declarations**: rejected. Device polls must join the freeze family under the replay discipline; PPUDATA reads perform non-status device actions and KIL is a halt with reset-only recovery, so neither declares.

## Decision

- **Synthesized VBL exit is canonical** for a `$2002` status poll (`BIT` or `LDA` followed immediately by its back-edge branch). At the counterfactual read tick the CPU drives the poll read (value, VBL clear, toggle reset, suppression check, latch update), sets the flags the poll opcode would set, applies LDA's A load, and moves PC past the back-edge branch as the executing loop would on that tick. An interrupt dispatch on the same tick takes precedence. Loop-top re-execution is the fallback when the shape is not covered (other poll opcodes, incomplete end records) and for ordinary interrupt/write wakes.
- **Device-poll freeze uses effect replay**: `$4015`/`$4016`/`$4017` polls declare on the same second-back-edge rule as other polls, with the same write-disqualification and DMA-precedence gates. Each frozen iteration presents the read's device-side effect at the loop's own cadence: APU interrupt flags clear, controller shift registers advance. No polled value is presented to the program; the real loop-top read after wake consumes the real device state. A pending or in-flight DMA pauses replay and keeps the bus.
- **A visible exit wakes a frozen poll early.** When the loop's next real read would take its exit branch, the freeze resumes instead of replaying device actions for iterations that cannot happen: the resumed read consumes the real value, and a replayed flag clear must never decide the exit. This covers the synthesized VBL exit and a device status that changed without a CPU write (an APU interrupt bit arriving, a controller shift result), for a poll read followed by its back edge, with or without a masking `AND #imm`. The projection peeks the device or the polled address and is side-effect free; a mispredicted wake only costs a loop-top re-execution, because the resumed read decides the branch again.
- **A device poll's replayed effect is not a bus read.** `$2002` status replay stays side-effect-only; PPUDATA polls are structurally excluded from declaration because their read refills the read buffer and increments VRAM address; KIL is excluded because it is a halt, not a poll. These exclusions are permanent.
- **Frozen wake reads published line levels only.** Each dot the machine publishes the /NMI line level and the combined (time-corrected APU and cartridge) IRQ level. The frozen path reads those levels through the existing machine-maintained edge latch and the published IRQ level, without calling the CPU's edge-latching detectors. It preserves the lagged-sample recognition semantics and the counterfactual wake remainder, so the loop-top read re-executes on the same dot as it would have while executing. Apart from wake dispatch, a frozen dot mutates no CPU state.
- **The frozen-dot harness contract is fixed** but unchanged in behavior: every frozen dot evaluates the plugin stop check, and plugin `end` is sampled once per frozen loop iteration at the loop's measured cadence with `peek`-only observation. This keeps reset-handshake timers and verdict-hang handling alive; the verdict logic itself is untouched, and no instruction boundary is fabricated.
- **Frame equivalence is the acceptance bar**: frozen versus never-frozen control must match in framebuffer bytes, register traces, and interrupt timing, including the `$2002` VBL wait, device polls, and the bare/RAM-flag wait cases already covered.

## Consequences

- The synthesized exit makes VBL suppression and cycle-counted initialization match unfrozen execution; adjusting wake phase to "fix" an off-grid resume would now be a regression, not a tuning change.
- Device effects advance at loop cadence during a freeze, so frozen and unfrozen input/IRQ loops leave the APU and controller state identical. Replaying a value or skipping the effect would break that equivalence.
- The frozen path never invokes edge detectors; CPU interrupt state can only change through normal execution or an actual wake dispatch. Moving edge latching back into the CPU would reintroduce frozen-dot state mutation.
- Harness plugins keep observing frozen loops at the loop's own cadence; speeding up `end` sampling or dropping the per-dot stop check would trip verdicts earlier than an executing loop. The verdict logic stays independent of freeze internals.
- PPUDATA and KIL remain non-declarable; broadening declaration to unclassified read effects would silently swallow device actions or change halt recovery.
- GLOSSARY.md gains the device-poll freeze discipline, wake-from-line-levels, frozen-dot harness contract, and counterfactual grid vocabulary, with avoid-terms that reject the superseded loop-top-only wording.
